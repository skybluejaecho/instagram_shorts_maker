# PC 이동과 제작 인수인계

다른 Windows PC에서도 같은 시리즈·회차·수정 요청을 이어갈 수 있도록, 사람이 읽는 요약과 기계가 확인하는 파일 목록을 함께 만든다. 기존 운영 파일을 수정하거나 외부 모델·TTS·렌더러를 호출하지 않는다.

## 남기는 기록

| 기록 | 역할 |
| --- | --- |
| 수동 `BRIEF.md`, `DECISIONS.md` | 시리즈 기획 의도·합의·변경 이유·남은 작업. 지원 설정과 실제 반영 위치를 연결한다. |
| 자동 `HANDOFF.md` | 시리즈·근거·기간·회차·실패·수정 요청의 생성 시점 요약과 새 PC 점검 순서. |
| 자동 `manifest.json` | 저장소 상대경로·파일 크기·SHA-256, 생성 PC의 기본 런타임, 구조화한 상태 요약. |
| 원본 카탈로그·입력·실행 기록·산출물 | 실제 재개·중복 검사·캐시·승인 버전을 결정하는 원본. Markdown으로 대체하지 않는다. |

시리즈 기획 양식은 [series-brief.md](../../planning/examples/series-brief.md)에 있다. 기본 수동 기록 위치는 `local/series/<시리즈 ID>/BRIEF.md`, `DECISIONS.md`다. 자동 생성기는 수동 기록을 읽을 위치만 안내하며 수정하거나 대신 작성하지 않는다.

현재 프로젝트의 합의와 외부 모델 실행 조건은 운영 데이터의 `local/PROJECT_NOTES.md`에 기록했다. 새 PC·새 채팅에서는 이 문서도 함께 읽는다. 인수인계 목록에는 포함되지만 생성 모델에 자동으로 전달되거나 전역 실행 제한으로 강제되는 것은 아니다.

현재 생성 모델은 시리즈의 지원 설정, 기존 회차 이력, 명시 등록된 근거 본문을 사용한다. 임의의 기획 Markdown·저장소 전체·이전 채팅은 자동 입력되지 않는다. 등록 근거는 저장소 내부 상대경로의 UTF-8 `.md`/`.txt`이며, 20개·개별 128 KiB·전체 512 KiB 제한을 적용한다. URL은 출처 기록이며 자동 다운로드하지 않는다. Drive에 있는 자료도 저장소 안에 복원해야 한다.

## 이전 PC에서 내보내기

기획·제작·수정·승인과 수동 편집을 끝낸 뒤 저장소 루트에서 실행한다.

```powershell
node pipeline/cli.cjs handoff export transfer-20261110
```

`local/handoffs/transfer-20261110/`에 `HANDOFF.md`, `manifest.json`을 생성한다. 같은 ID를 덮어쓰지 않으므로 다음 인수인계에는 새 ID를 사용한다. 실행 중인 작업 잠금을 조회하고 수집 전후 파일 해시가 달라지면 생성을 중단한다. 저장소 전체를 잠그지는 않으므로 수집 중·이동 중에도 쓰기 작업을 시작하지 않는다.

목록에는 코드·템플릿·자료·수동 기획 기록·`planning/catalog.json`·`planning/inputs/`·`runs/`·`renders/`·기존 샘플 생성물이 포함된다. Git의 제외 규칙을 그대로 백업 제외 규칙으로 쓰지 않는다. `.git`, `node_modules`, `.hyperframes`, 인증 환경 파일·`secrets`, 루트 `backups`, `local/handoffs`는 목록에서 제외한다. `.env.example`과 `.env.*.example`은 포함한다. 링크·junction은 따라가지 않고 오류로 기록한다. 알려진 제외 규칙이 모든 비밀정보를 탐지하는 것은 아니다.

**이 명령은 파일 복사·압축·업로드·백업을 수행하지 않는다.** manifest의 파일 전부와 생성한 인수인계 폴더를 직접 Drive/외장 디스크 등에 함께 복사한다. `local/handoffs`를 제외한 이유는 과거 인수인계끼리 재귀 참조하지 않기 위해서이며, 이동에 사용할 인수인계 폴더 자체는 반드시 별도로 포함해야 한다.

원본 코드도 함께 옮긴다. Git clone만으로 운영 파일을 가져올 수 없으며, 줄바꿈 변환·다른 코드 버전도 파일 해시와 기존 산출물 재사용 판정을 바꿀 수 있다. 키·로그인은 따로 준비하고, 인수인계와 모델 응답 등 운영 로그는 비공개로 보관한다.

누락된 등록 근거·참조 입력이 있으면 확인 사항을 문서에 남기며 종료 코드 1을 반환한다. 문제를 해결하고 새 ID로 다시 생성한다. 오류가 없는 문서도 실제 파일이 안전하게 복사됐다는 증거는 아니다.

## 새 PC에서 확인하기

기존 폴더를 덮어쓰지 않고 별도 폴더에 상대경로 구조를 유지하여 복원한다. 저장소의 절대 경로는 달라도 된다.

```powershell
node pipeline/cli.cjs handoff check transfer-20261110
node pipeline/cli.cjs handoff check transfer-20261110 --json
```

manifest와 Markdown, 모든 대상 파일을 읽어 누락·바이트 변경·경로 이탈을 확인한다. 파일을 수정하거나 새 제작을 시작하지 않는다. 대상 파일이 일치하고 내보내기 당시 자료 오류가 없으면 종료 코드 0, 그렇지 않으면 1이다. 새로 추가된 파일은 `unexpectedFiles`에 표시하지만 기존 스냅샷 파일의 일치 여부와 구분한다. 최신 작업까지 보존했는지 확인하려면 마지막 변경 후 새 인수인계를 생성해야 한다.

파일 검사는 실행 환경·영상 품질 검사가 아니다. 새 PC에는 Windows, Node.js, HyperFrames, FFmpeg·ffprobe, Chrome, 같은 한국어 System.Speech 음성·글꼴을 별도로 준비한다. 필요하면 기존 `HYPERFRAMES_*` 환경 변수로 도구 위치를 지정한다. 현재는 macOS/Linux에서 기존 Windows 음성 제작을 그대로 재개한다고 보장하지 않는다.

도구와 운영 조건을 확인한 뒤 다음 읽기 전용 명령으로 실제 상태를 확인한다.

```powershell
node pipeline/cli.cjs series check local/my-series/series.json
node pipeline/cli.cjs period status <기간-ID>
node pipeline/cli.cjs review list <제작-묶음-ID>
node pipeline/cli.cjs status <회차-ID>
```

설정 파일 경로는 실제 보관 위치로 바꾼다. `series check`는 한국어 음성·자료를 점검하지만 렌더러 전체를 시험하지 않는다. `run/resume/review apply`는 모델·미디어 제작을 실행할 수 있으므로 단순 이동 검사로 실행하지 않는다. 재개 시에는 이전 기간·묶음·회차·수정 요청 ID를 유지한다.

## 경로와 기존 기록 호환

완료 회차의 단계 경로와 해시·승인 Revision은 저장소 루트와 분리되어 있다. 문구 자동 보완의 신규 journal은 상대경로를 저장하며, 기존 절대경로 journal도 해시로 검증된 회차 상대경로를 현재 루트에서 해석한다. 중단된 입력 반영을 새 루트에서 재개해도 이전 PC 경로에는 쓰지 않는다.

과거 검수 HTML·기획/수정 보고서에는 이전 PC의 절대 링크가 남을 수 있다. 원본 기록의 경로를 일괄 치환하면 해시와 승인 버전이 달라질 수 있으므로 수정하지 않는다. 현재 상태 조회의 MP4 경로와 인수인계의 상대경로 목록을 사용한다. 모든 전용 어댑터·과거 보고서 링크의 자동 이전까지 보장하는 기능은 아니다.

Drive 동기화는 두 PC 사이의 실행 잠금이 아니다. 기존 PC 작업 종료 → 복사·동기화 완료 → 새 PC 파일 검사 → 한 PC에서 재개의 순서를 지킨다. 병합된 카탈로그나 불완전한 폴더를 임의로 이어 붙이지 않는다.
