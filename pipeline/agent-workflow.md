# Codex와 시리즈를 운영하는 순서

대화하는 Codex는 사용자의 기획을 문서·설정·회차 명세로 구체화하고 적절한 CLI를 실행한다. Node.js 실행기는 상태·검수·재시도·재사용을 관리한다. 파이프라인 내부 모델은 전달받은 설정·이력·근거로 기획·판정을 만든다. 내부 provider는 저장소 문서 자동 로딩을 끄므로, 루트 `AGENTS.md`와 임의 기획 Markdown이 그 모델에 자동 전달되지는 않는다.

## 처음 실제 시리즈를 시작할 때

1. **기획서 1차 작성.** 주제, 시청자, 전달할 가치, 반복 가능한 회차 구조, 사용할 자료, 화면 분위기를 정한다. [양식](../planning/examples/series-brief.md)을 `local/series/<ID>/BRIEF.md`에 작성하고 확정·제안·미결정을 구분한다. 미정 내용을 확정된 설정으로 등록하지 않는다.
2. **제작 가능 범위 연결.** 요구사항을 현재 설정으로 가능 / 새 장면·컴포넌트 구현 필요 / 후속 확장으로 나눈다. [공통 명세](story/README.md), [내용 검증](content/README.md), [화면 검수](visual/README.md)를 필요한 범위만 확인한다. 전용 어댑터를 붙일 수 있어도 자동 기획·근거 검증 등 공통 story 전용 경로까지 자동으로 지원되는 것은 아니다.
3. **대표 회차 1편의 명세 작성.** 화면·낭독·장면·음성 큐를 정하고 등록 설정과 근거 자료를 준비한다. 사용자가 기획만 요청했다면 여기까지 문서로 구체화하며 `--plan-only`를 대신 실행하지 않는다. 시리즈 설정은 `series check`로 로컬 점검할 수 있다.
4. **대표편 제작과 기준 확정.** 제작이 요청된 범위에서 등록·기획 연결·제작·검수·수정을 진행한다. 사용자가 확인한 대표편 ID·Revision과 확정된 제작 규칙을 기록한다. 입력·자료·정책을 바꾼 뒤 기존 승인을 그대로 적용하지 않는다.
5. **첫 5편 운영.** 5편의 주제·학습 목표·서로 다른 설명 관점을 먼저 확인하고 기간 계획으로 제작한다. 반복 가능한 포맷인지 확인한 뒤 5~30편씩 늘린다. 자동 기획 또는 준비된 기획의 `planIds` 연결 중 현재 실행 조건에 맞는 방식을 선택한다.
6. **다음 기간 반복.** 같은 시리즈의 이력을 유지하고 새 기간 ID로 진행한다. 수정·실패 재개는 기존 ID를 사용한다. 합의와 남은 작업을 기록하고 인수인계가 필요하면 새 스냅샷을 만든다.

## 명령 선택

아래는 저장소 루트의 `node pipeline/cli.cjs` 뒤에 붙이는 명령이다. 꺾쇠 부분은 실제 경로·ID로 바꾼다. 요청과 기존 승인 범위 안에서 실행한다.

| 목적 | 명령 예시 | 영향 |
| --- | --- | --- |
| 기능 확인 | `--help` | 읽기 전용 |
| 현재 시리즈·기간·회차 확인 | `series list`, `period list`, `period status <ID>`, `batch status <ID>`, `status <회차-ID>` | 모델·제작 실행 없음 |
| 최종 검토·요청 확인 | `review list <묶음-ID>`, `review scenes <회차-ID>`, `review revision <요청-ID>` | 조회만 수행 |
| 등록 준비 확인 | `series check <설정.json> --json` | 로컬 파일·설치 음성 조회. 등록·합성 없음 |
| 시리즈·기획 등록 | `series register <설정.json>`, `plan add <시리즈-ID> <기획.json>` | 카탈로그 등 로컬 상태 변경 |
| 준비된 회차 묶기 | `plan batch <시리즈-ID> <묶음-ID> --plans <기획-ID목록>` | 회차 입력과 묶음 등록 |
| 기간 계획 저장 | `period create <기간.json>` | 게시 예정·연결 계획 저장. 즉시 제작하지 않음 |
| 자동 기획 | `generate <시리즈-ID> <묶음-ID> --count 5` | 모델·TTS·제작 가능. 한 묶음 1~10편 |
| 기간 실행·재개 | `period run <ID>`, `period resume <ID>`, `period retry-failed <ID>` | 필요한 기획·검수 모델과 미디어 제작 가능 |
| 개별·묶음 제작 | `run <회차-ID>`, `batch run <ID>`, `batch retry-failed <ID>` | 정책에 따른 내용 검사·보완 모델과 미디어 제작 가능 |
| 별도 내용·중복 검사 | `content audit <시리즈-ID> --plans <기획-ID목록>`, `plan audit <시리즈-ID> --plans <기획-ID목록>` | 모델 호출 및 검사 기록 생성 가능 |
| 별도 화면 검사 | `visual audit <회차-ID>` | 브라우저 실행·보고서 생성. 단순 조회가 아님 |
| 수정 요청 기록 | `review request-changes <회차-ID> --revision <현재-Revision> --target <장면-ID> --note "요청"` | 로컬 검토 기록 변경 |
| 요청 반영·재제작 | `review apply <회차-ID> --request <요청-ID> --scope visual` | 모델 패치·검수·필요한 제작 단계 실행 |
| 사람이 확인한 결과 승인 | `review approve <회차-ID> --revision <현재-Revision>` | 승인 기록 저장. 게시 기능 아님 |
| 인수인계 생성·복원 검사 | `handoff export <새-ID>`, `handoff check <ID>` | export는 MD·manifest 생성, check는 파일 검사. 복사·업로드 없음 |

`generate/period ... --plan-only`는 자동 생성 모드에서 모델과 실제 TTS·타이밍 검사를 수행하고 MP4 전에 멈춘다. 외부 호출 없는 초안 작성이나 무료 dry-run 옵션으로 취급하지 않는다. 준비된 `planIds`도 제작 시 필수 내용 검증이 설정돼 있으면 모델을 사용할 수 있다.

30편은 기간 계획에서 `batchSize` 단위로 나눈다. 기획 묶음은 순차로 최신 이력을 확인하고, 등록된 회차는 병렬 제작할 수 있다. 제작 중 한 회차가 실패해도 다른 회차는 계속하지만, 등록 전 기획 후보의 보류는 해당 기획 묶음 등록을 막을 수 있다. [기간 제작 안내](period/README.md)를 따른다.

## 수정·재개 판단

- 화면 문구만 바뀌면 기존 음성을 유지하고 필요한 화면·영상 단계부터 진행한다. 낭독·음성 설정이 바뀌면 음성과 타이밍을 다시 만든다.
- 최대 두 번의 제작 문구 보완은 지원되는 제목·본문의 조건 누락·모호함에 한정된다. 근거 부족·애니메이션 설계·화면 잘림을 모두 자동 해결하는 기능으로 취급하지 않는다.
- 사람의 `review apply`도 현재는 대상 장면의 화면 문구·낭독문을 수정한다. 배치·장면 구조·음성·디자인 변경은 지원 범위에 맞는 명세·템플릿 변경으로 처리한다.
- 같은 보류 상태를 반복 실행해 수정 한도를 초기화하지 않는다. 원인과 자료를 보완한 뒤 재개한다. 최종 영상은 사용자의 확인 대상으로 남긴다.

## 작업을 마칠 때 남길 내용

시리즈 문서에 날짜, 결정과 이유, 실제 반영 파일, 기준 회차·Revision, 미결정 사항, 다음 작업을 기록한다. 사람·AI의 대화 요약과 CLI 원본 상태를 구분하고 비밀값을 문서에 넣지 않는다. 생성된 인수인계는 시점 스냅샷이므로 그 후 문서·코드·영상이 바뀌면 PC 이동 직전에 새 ID로 생성한다. 과거 snapshot의 manifest를 최신 상태에 맞춰 덮어쓰지 않는다.

기존 작업을 재개할 때 운영 파일이 빠져 있으면 먼저 해당 인수인계의 복원 범위를 확인한다. [이동 안내](handoff/README.md)대로 파일을 복원·검사하고 현재 상태를 조회한다. 도구·한국어 음성·글꼴 확인은 파일 무결성 확인과 별개다.

## 새 채팅 시작 요청 예시

> 이 저장소의 AGENTS.md와 에이전트 작업 흐름, local/PROJECT_NOTES.md를 읽어줘. 새 시리즈를 기획하려고 해. 주제는 ○○, 시청자는 ○○이고 자료는 ○○에 있어. 우선 기획서 1차와 현재 렌더러 지원 여부까지만 정리해줘. 아직 추가 모델 호출·TTS·영상 제작은 진행하지 마.

Codex의 저장소 지침 로딩 방식은 [OpenAI 공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 참고한다. 이 문서 추가를 실제 새 Codex 세션에서의 모델 실행 검증과 동일시하지 않는다. 내부 파이프라인 모델의 자료 입력 범위는 별도의 생성 계약으로 정해진다.
