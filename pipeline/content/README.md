# 제작 전 내용 검증과 근거 기록

시리즈에 등록한 자료의 실제 본문을 생성 모델과 검증 모델에 제공한다. 대본·화면 문구를 자료에 대조하고, 오류 회차만 수정하거나 근거 부족을 검토 대기로 남긴다. 현재 공통 장면 어댑터 `pipeline/story/adapter.cjs`에서 지원한다. 검증 범위는 등록된 자료와의 일치이며, 모든 사실의 진위나 최신성을 보장하는 기능은 아니다.

## 시리즈 설정과 자료 준비

시리즈 JSON에 `contentReview`를 넣거나, 기존 시리즈의 자료 정책만 별도 명령으로 변경한다.

```json
{
  "mode": "required",
  "sources": [{
    "id": "python-structures",
    "title": "스택·큐 확인 노트",
    "path": "samples/content/sources/python-structures.md",
    "url": "https://docs.python.org/3/tutorial/datastructures.html"
  }]
}
```

```powershell
node pipeline/cli.cjs series sources story-demo samples/content/policy.json
node pipeline/cli.cjs content sources story-demo
node pipeline/cli.cjs generate story-demo sourced-cs-01 --count 2 --plan-only
```

- `required`: 자료와 내용 검사 통과가 제작 조건이다. 미설정 시리즈는 기존 동작을 유지하며 검증 완료로 표시하지 않는다. 명시적으로 끄려면 `{"mode":"off","sources":[]}`를 사용한다.
- `path`: 저장소 내부 UTF-8 `.md`/`.txt` 파일이다. 직접 정리한 자료, 사용 허용된 발췌문 등을 등록한다. 원문·번역·요약 여부, 확인일, 출처, 적용 범위와 조건을 자료에 명시하면 검토하기 쉽다.
- `url`: 출처 표시용이다. 주소가 있다고 검증을 통과시키거나 실행 중 자동 다운로드하지 않는다. 모델이 출처 URL을 생성하지도 않는다. 웹 자료 갱신은 현재 수동이다.
- 최대 자료 20개, 자료당 128 KiB, 전체 512 KiB이다. 누락·빈 파일·잘못된 인코딩·읽기 실패·크기 초과는 보류 사유이며 해당 자료를 몰래 생략하지 않는다. 저장소 밖으로 나가는 실제 경로도 거부한다.
- 시리즈 설정을 변경한 뒤에는 새 생성 묶음 ID를 사용한다. 기존 회차에 정책을 켜면 이후 재실행·승인 검토에서 새 검증 단계가 필요하다. 다른 어댑터에는 `required`를 설정할 수 없다.

검증용 CS 자료는 Python·Qt 공식 문서를 확인해 작성한 **로컬 참고 노트**다. 웹 원문 전체나 자동 수집한 원문으로 표시하지 않는다. 기존 `story-demo` 설정과 영상은 유지하고, 실제 통합 검증은 별도 `content-cs-demo` 시리즈에서 동일한 CS 예제를 사용한다.

## 생성과 수정 흐름

`실제 자료 읽기 → 자료를 포함해 회차 생성 → 의미 중복 검사 → 내용·근거 검사 → 실제 TTS·타이밍 검사 → 묶음 등록 → 제작 전 내용 검사 → HTML·MP4 → 기술 검수 → 최종 확인`

일반 제작 명령에서 제목·장면 문구의 조건 누락이나 모호함으로 보류되면, 기존 근거와 검증된 낭독 범위 안에서 최대 두 번 패치를 제안하고 재검수한다. 근거 부족과 수정 범위 밖 문제는 `needs_review`로 남긴다. 한도는 같은 입력·자료 기준으로 재실행에도 유지되며, 기존 음성과 다른 완료 회차를 보존한다. [제작 문구 자동 수정 안내](repair-README.md)를 참고한다.

내용 검사는 제목, 학습 목표, 모든 낭독 구간, 장면 제목·본문·카드 문구를 고정 ID로 나눠 전부 확인한다. 질문에 포함된 잘못된 전제도 검토하고, 화면 설명과 음성·카드 순서가 충돌하는지 회차별로 별도 판정한다. 코드가 항목 누락·중복·알 수 없는 ID를 거절한다.

| 결과 | 처리 |
| --- | --- |
| `supported` | 주장을 뒷받침하는 실제 자료 ID·근거 구절·판정 이유 기록 |
| `contradicted` | 자료와 모순되거나 필요한 조건을 빠뜨림. `corrections`로 해당 회차만 수정 |
| `uncertain` | 근거 부족·해석 불가. `needs_review`로 중단 |
| `not_factual` | 순수 질문·가상 입력의 이름 등. 사실 주장이 아닌 이유 기록 |

`supported`/`contradicted`는 근거 구절이 실제 스냅샷에 존재해야 한다. 가짜 인용·등록하지 않은 출처는 검사 실패다. 사실 검증 항목이 하나도 없는 회차도 자동 통과시키지 않는다. 모델이 단순히 ‘맞다’고 응답하거나 URL만 제시하는 것으로는 통과하지 않는다.

생성 단계에서 오류 회차만 교체하고 다른 회차의 원본 객체는 유지한다. 수정 후에는 중복 검사와 내용 검사를 다시 실행한다. TTS 길이 보완으로 대본이 바뀐 경우도 동일하다. `--attempts`는 기존처럼 내용 생성·수정 호출 횟수이며, 검증 모델 호출은 별도다. 모호함이나 수정 횟수 소진은 검토 대기로 남긴다. 이번 범위에는 강제 통과 명령이 없다.

직접 `run`, 수동 기획의 `plan batch` 후 제작, `review apply` 수정 경로에도 required 정책을 적용한다. 보류된 내용은 음성을 합성하거나 수정 입력으로 반영하지 않는다. 최종 승인은 사람이 기록한다.

## 기록·조회·재개

```powershell
node pipeline/cli.cjs generate status sourced-cs-01
node pipeline/cli.cjs content audit story-demo --plans stack,queue
node pipeline/cli.cjs review list sourced-cs-01
```

`content audit`은 현재 입력을 검사하고 새 보고서를 저장한다. 기획·영상·승인 상태를 수정하지 않는다. 1–10개 회차를 선택하며 완성된 공통 장면 입력이 필요하다. off 정책은 `disabled`로 표시하며 통과로 취급하지 않는다.

- 생성 기록: `runs/_generation/<묶음>/content-*/decision.json`
- 제작 기록: `runs/<회차>/artifacts/content/<버전>/report.json`
- 단독 검사: `runs/_content/<검사>/check-*/report.json`
- 수정 검사: `runs/_revisions/<요청>/check-*/content/report.json`

보고서에는 원문 항목·핵심 주장·판정·근거 구절·출처·회차 내 일관성·한계를 남긴다. 같은 검사 폴더의 `source.json`은 읽은 자료 본문과 해시, 검토한 입력을 보존한다. 프롬프트·모델 응답·사용량도 함께 남긴다. 기획의 `references`에는 실제 판정에서 인용한 출처만 기록하고 생성 카탈로그의 `contentReview`에서 보고서를 연결한다. `referencesVerified: true`는 **등록 자료에 근거한 검증을 통과했다는 뜻**이며 웹 원문의 최신성을 조회했다는 뜻이 아니다.

생성의 `content_check`는 검사 중, `content_failed`는 모델·응답·자료 변경 등으로 검사 실패, `needs_review`는 검토가 필요한 상태다. 같은 생성 명령으로 재개하면 저장된 후보를 최신 자료로 다시 검사한다. 근거 부족은 자료를 보완한 뒤 재개할 수 있다. 수정 요청도 보류 후보와 이유를 보존한다. 일반 회차 제작에서는 자동 수정 후에도 검토가 필요한 경우 `needs_review`로 표시하며, 모델 연결·파일 오류 등은 `failed`로 구별한다. 내용 보고서와 `contentRepair` 기록에서 상세 사유를 확인할 수 있다.

자료·대본 해시는 검증과 등록에 연결하고 등록 직전에 자료를 재확인한다. 제작 도중 입력이나 자료가 바뀌어도 오래된 판정으로 진행하지 않는다. 내용 검사만 다시 필요한 경우에는 검사를 먼저 통과한 뒤 변경되지 않은 음성 산출물을 재사용한다. 낭독문·음성 설정이 바뀌면 기존 규칙대로 다시 합성한다.

## 재현 가능한 검증

일반 테스트는 가짜 모델을 주입해 경계 조건과 복구 동작을 검사한다. 아래 두 명령은 기존 로그인으로 **실제 모델 이용량과 실행 시간**을 사용한다.

```powershell
# 기존 CS 예제의 정상·오류·근거 부족 판정과 자료 누락 확인
node pipeline/content/validate-samples.cjs

# 의도적으로 화면 순서를 틀린 CS 예제 → 실제 모델 수정 → TTS → MP4 한 편
node pipeline/content/validate-workflow.cjs
```

첫 명령은 기존 입력을 복사해 메모리에서 검증 사례를 만든다. 두 번째는 통제된 오류를 넣은 첫 후보를 사용하고, 판정·수정·TTS·렌더링을 실제 구현으로 실행한다. `content-cs-demo`/`content-cs-01` 이름을 사용하며 같은 명령으로 중단 재개할 수 있다. 생성 두 편 중 수정된 스택 한 편을 MP4로 제작하고 최종 검토 대기로 남긴다.

현재 생성 단계의 보고서를 최초 제작 단계에서 재사용하는 캐시는 없어 검증 호출이 추가된다. 모델의 논리적 판단, 자료의 신뢰성·최신성에는 한계가 있다. 시각적 잘림·겹침, 실제 발음과 음성 싱크 품질, 게시 일정·자동 게시 기능은 이 검사의 범위 밖이다.

화면 잘림·겹침·읽기 시간은 별도 [visual 검수 단계](../visual/README.md)에서 검사한다. 화면 검수의 임계값만 바꾸면 내용 검증 모델은 다시 호출하지 않는다.
