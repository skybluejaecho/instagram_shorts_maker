# 제작 단계 제목·화면 문구 자동 수정

일반 제작 명령은 내용 검수가 보류한 제목·화면 문구를 최대 두 번 자동 보완하고 다시 검사한다. 공통 장면 어댑터와 `contentReview.mode: required` 시리즈에서 적용한다. `run`, `batch run`, `batch retry-failed`, `period run/resume/retry-failed`, 자동 생성 뒤 제작에 연결된다.

```powershell
node pipeline/cli.cjs run <회차 ID>
node pipeline/cli.cjs status <회차 ID>
node pipeline/cli.cjs period retry-failed <기간 ID>
```

## 수정 대상

검수 보고서의 미해결 항목이 회차 제목 또는 장면 제목·본문에 한정돼 있고, 등록 자료와 이미 검증된 낭독·학습 목표로 의도를 확인할 수 있어야 한다. 모델은 적용 조건 누락과 모호한 표현을 좁게 보완하는 패치를 제안한다. 예를 들어 가득 찬 deque의 동작을 묻는 제목에 `Python maxlen deque`와 `append`를 명시한다.

- 회차 제목을 바꾸면 기획의 제목과 제작 입력의 제목을 함께 갱신한다.
- 문제 장면의 `headline`·`body`만 수정할 수 있다. 근거 구절과 원래 지식에 대한 연결을 검사한다.
- 주제 식별자·학습 목표·낭독·음성·카드·배치·전환·강조 동작과 장면 순서는 보존한다.
- 후보 입력은 규격 검사와 내용 재검수를 통과한 뒤 반영한다. 이후 일반 제작의 실제 HTML 화면 검수와 MP4 기술 검수도 실행한다.

자료가 없거나 읽을 수 없는 경우, 낭독·학습 목표·카드 등 수정 범위 밖의 항목이 미해결인 경우는 검토 대기로 남긴다. 문구 자체의 근거가 부족하면 다른 지식으로 바꿔 통과시키지 않고 보류한다. 후보의 인용은 실제 등록 자료 안에 있어야 하며, 마지막 내용 판정도 동일한 입력과 자료 해시로 검증한다.

## 두 번 제한과 재개

두 번은 같은 미해결 입력·근거 자료 조합에 대한 누적 제안 한도다. 다시 `run`이나 `retry-failed`를 실행해도 한도가 초기화되지 않는다. 자료나 입력이 그대로인 검토 대기는 새 내용 검사나 수정 모델을 반복 호출하지 않는다. 자료·입력을 실제로 보완한 뒤 재개하면 새로운 조건으로 검사한다.

중단 후에는 저장된 후보·검수 결과와 제목 반영 기록부터 복구한다. 이미 통과한 검수는 입력·자료 해시가 일치할 때 그대로 사용하므로 새 판정 호출이 없다. 회차 파일과 기획 제목 중 하나만 반영된 상태도 새 제작을 시작하기 전에 맞춘다. 검사 결과가 아직 없는 후보는 해당 검사부터 이어간다.

수정 가능한 후보도 두 번 안에 통과하지 못하면 `needs_review`로 남기며 원본을 보존한다. 모델 연결·파일 입출력 오류는 운영 오류로 별도 기록한다. 이 기능의 두 번 제한은 자동 기획용 `--attempts`와 별개이며 해당 옵션으로 늘어나지 않는다.

음성 입력이 바뀌지 않으므로 기존 음성이 있다면 같은 WAV와 타이밍을 재사용한다. 새 문구에 필요한 HTML·화면 검수·영상만 다시 만든다. 다른 완료 회차의 파일과 승인 기록은 수정하지 않는다. 수정한 회차의 새 결과는 `ready_for_review`로 돌아가 최종 확인을 기다린다.

## 기록과 범위

수정 제안·원본·후보·근거·내용 재검수·반영 전후 입력 해시를 `runs/_content-repairs/`에 보존한다. 회차 상태의 `contentRepair`에 결과, 사유, 누적 시도와 보고서 경로를 연결한다. CLI 상태와 기간 보고서에서 이 기록을 볼 수 있다. 제작 묶음은 보류 회차를 `needs_review`로 표시하고 나머지 회차를 계속 실행한다.

코드의 일반 제작 진입점은 `pipeline/production.cjs`의 `runProduction`이다. 검사 전용 호출과 명시적인 수정 요청은 입력 변경 범위를 지키기 위해 기존 저수준 `runEpisode` 경로를 유지한다. `status`, `visual audit`, `content audit`는 자동 수정이나 모델 제안을 실행하지 않는다.

이 기능은 글자 잘림·애니메이션·단어 단위 싱크의 자동 보정 기능은 아니다. 해당 문제는 화면 검수 또는 사람의 최종 검토 대상으로 유지한다.
