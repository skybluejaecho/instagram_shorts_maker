# 제작 전 의미 중복 검사

새 `generate` 실행은 기획·대본 JSON을 만든 뒤 TTS보다 먼저 기존 이력과 새 회차끼리 비교한다. 같은 핵심 지식을 다른 제목·비유로 반복하는지 확인하고, 중복 회차만 대체한다. 사람의 최종 영상 검토와 외부 출처 기반 사실 검증은 별도다.

## 판정 기준

| 판정 | 기준 | 자동 처리 |
| --- | --- | --- |
| `duplicate` | 배우는 핵심 원리가 같음. 제목·숫자·비유·설명 순서만 달라도 중복 | 해당 회차만 다시 기획 |
| `distinct` | 같은 분야라도 구체적인 학습 목표·원리가 다름 | 다른 회차 검사를 통과하면 제작 진행 |
| `uncertain` | 설명이 너무 추상적이거나 구별할 근거가 부족함 | `needs_review`; TTS·묶음 등록 전에 중단 |

스택의 후입선출을 카드 대신 책으로 설명하는 것은 중복으로 볼 수 있다. 후입선출 순서와 고정 용량 스택의 오버플로는 다른 지식이다. 공통 배경이나 A/B 예시를 함께 쓴다는 이유만으로 중복 판정하지 않도록 지시한다. `topicKey`, 제목, 학습 목표가 정규화 후 같으면 코드가 중복으로 판정하며 모델이 뒤집을 수 없다.

## 이력과 비교 범위

초안·제작 중·제작 완료·게시된 기획 모두를 시리즈 안에서 비교한다. 회차로 생성된 기획은 현재 `catalog.episodes`가 연결한 입력의 낭독문을 사용하므로 수정 요청으로 바뀐 내용도 반영한다. 아직 회차가 없으면 기획의 `input`을 읽고, 입력 없는 초안은 제목·목표·설명 방식으로 비교한다. 지정된 입력 파일이 누락되거나 저장소 밖을 가리키면 이력을 생략하지 않고 오류로 멈춘다.

이력은 20개씩 나누어 전부 검사한다. 각 후보와 모든 기존 이력의 조합, 이번 묶음의 모든 회차 조합이 포함된다. 모델 응답이 비교 항목이나 후보 요약을 누락하거나 알 수 없는 ID를 반환하면 통과시키지 않는다. 새 묶음 안에서 두 회차가 중복이면 순서상 뒤 회차를 교체 대상으로 삼는다.

모델은 후보마다 `knowledge.core`에 핵심 지식을, `knowledge.example`에 제공된 예시를 요약한다. 설명 방식은 기존 `angle`에 남는다. 의미·음성 검사를 통과해 등록된 기획에는 이 요약을 저장한다. 기존 요약과 최신 낭독문이 다르면 최신 낭독문을 우선해 판단한다.

## 실행과 조회

```powershell
# 새 회차: 의미 검사 통과 뒤 TTS 실측·묶음 등록까지만
node pipeline/cli.cjs generate story-demo novelty-cs-02 --count 2 --plan-only
node pipeline/cli.cjs generate status novelty-cs-02

# 이미 등록된 기획을 선택해 다시 비교; 영상·기획 원본은 변경하지 않는다
node pipeline/cli.cjs plan audit story-demo --plans stack,auto-cs-01-01

# 가상 데이터의 완전 중복·표현 변경·별개 지식을 실제 모델로 검증
node pipeline/novelty/validate-samples.cjs
```

`plan audit`은 선택한 1–10개 기획을 나머지 이력 및 선택한 기획끼리 비교한다. 기존 회차를 수정하거나 제작을 취소하지 않는다. 보고서는 `runs/_novelty/`에 남고 중복·판단 보류가 있으면 종료 코드 1을 반환한다. `validate-samples.cjs`는 `samples/novelty/cases.json`의 가상 이력을 사용하는 실제 모델 평가이며 일반 단위 테스트와 분리되어 있다.

자동 생성 중에는 `runs/_generation/<묶음 ID>/`의 상태와 의미 검수 보고서를 보존한다. 원본 비교 입력, 이력 청크, 판정 이유, 핵심 요약, 모델 응답과 사용량을 볼 수 있다. 등록 기록에는 당시 이력 해시와 보고서 경로·해시가 남는다.

## 부분 재기획과 중단 복구

중복 회차만 대체할 새 기획·대본·장면 JSON을 요청하고, 나머지 회차의 원본 객체는 코드가 유지한다. 새 후보를 합친 뒤 전체 비교를 다시 수행하므로 교체한 회차가 보존 회차와 겹치는지도 확인한다. 교체 후 특정 회차의 음성 길이가 실패해도 해당 회차만 타이밍을 수정하고 다른 회차는 보존한다.

`--attempts` 기본 3회는 이번 명령에서 내용 생성·재기획에 사용할 호출 수다. 소진한 뒤에도 중복이면 후보와 이유를 저장하고 `needs_review`로 멈춘다. `uncertain`은 자동 재기획하지 않고 즉시 검토 대상으로 남긴다. 보류 보고서를 확인하고 기존 초안의 모호한 학습 목표 등을 `plan update`로 보완한 뒤 같은 생성 명령으로 다시 검사할 수 있다. 판정을 사람이 강제로 통과시키는 명령은 이번 범위에 포함하지 않는다.

검사 모델·접속·이력 읽기 실패는 후보를 보존하고 중단한다. 같은 명령으로 재개하면 내용을 처음부터 만들지 않고 저장된 후보와 최신 이력을 다시 검사한다. 등록 직전에도 이력 해시를 재확인하므로 다른 묶음이나 기존 회차 변경으로 이력이 바뀌면 오래된 판정으로 등록하지 않는다. 이미 등록된 묶음은 기존 동작대로 재사용하며 자동 소급 검수하지 않는다.

## 현재 범위

의미 검사는 모델 판단이므로 완전한 중복 방지를 보장하지 않는다. 판정 이유와 보류 처리를 남겨 검토할 수 있게 한다. 이 모듈 자체는 사실·출처 검증을 수행하지 않아 결과에 `factChecked: false`를 기록한다. 등록 자료에 대한 내용 검증은 별도 [content 모듈](../content/README.md)에서 시리즈 정책에 따라 실행한다.

현재는 전체 비교 방식이다. 후보 수와 이력 수가 늘면 비교량과 모델 이용량도 증가한다. 후보는 한 번에 최대 10개이며 이력 20개마다 검사 모델 호출이 발생한다. 재기획 뒤와 중단 재개 시에도 다시 검사한다. 임베딩 검색·검사 캐시·장기 이력 색인은 추후 확장 항목이다. 기존 수동 `plan batch` 경로에는 이 자동 생성 검사가 강제되지 않으므로 필요하면 먼저 `plan audit`을 실행한다.
