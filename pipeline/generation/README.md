# 시리즈 다음 회차 자동 생성

## 실행 흐름

`시리즈 설정 + 최신 회차 이력 + 등록 근거 자료 → Codex 구조화 출력 → 명세 검사 → 핵심 지식·의미 중복 검사 → 중복 회차만 재기획 → 내용·근거 검사 및 오류 회차 수정(필수 정책 시) → 실제 TTS·장면 타이밍 검사 → 기획·회차·제작 묶음 저장 → HTML·MP4 제작 → 기술 검수 → 사람의 최종 검토`

현재 `pipeline/story/adapter.cjs`를 사용하는 시리즈에 연결되어 있다. 주제·대상·말투는 시리즈 설정에서 읽고, 길이·음성·색상·전환 속도는 생성 모델이 변경할 수 없다. 모델은 회차의 제목, 지식 식별자, 학습 목표, 설명 방식, 낭독문과 장면 데이터만 반환한다. 질문·설명·카드·결론, 카드 강조와 장면 사이 이어지는 이동을 활용한다.

## 명령

```powershell
# 기획부터 최종 검토 대기까지
node pipeline/cli.cjs generate story-demo auto-cs-02 --count 3 --jobs 2

# 기획·실측 검사·묶음 등록까지만
node pipeline/cli.cjs generate story-demo auto-cs-03 --count 2 --plan-only

# 생성 기록과 회차별 제작·검토 상태
node pipeline/cli.cjs generate status auto-cs-02
node pipeline/cli.cjs batch status auto-cs-02
node pipeline/cli.cjs review list auto-cs-02

# 실패 회차의 제작 재시도
node pipeline/cli.cjs batch retry-failed auto-cs-02 --jobs 2
```

`--count 1..10`은 필수이며 `--jobs 1..8`은 기본 1, `--attempts 1..5`는 기본 3이다. 회차 기획은 묶음 전체를 한 번에 생성해 서로 다른 지식을 다루게 하고, 음성 실측은 회차별로 수행한다. 제작은 기존 batch 실행기가 관리한다. 여러 기간에 대한 장기 계획은 여러 묶음으로 나눌 수 있으며, 이 명령은 게시 날짜를 자동 지정하지 않는다.

실제 제작은 HTML 준비 뒤 `visual` 화면 검수도 통과해야 MP4로 진행한다. 잘림·화면 이탈은 제작 실패로 남고, 겹침·읽기 시간 경고는 최종 검토에서 확인한다. `--plan-only`는 이 제작 전 단계에서 멈춘다. [화면 검수 안내](../visual/README.md)를 참고한다.

## 모델 연결

Codex CLI와 로그인이 필요하다. `codex login status`로 확인하고 필요하면 `codex login`을 실행한다. Windows의 기본 Codex 설치 위치와 PATH에서 실행 파일을 찾는다. 다른 위치는 `CODEX_CLI`에 `.exe` 또는 Node 진입 파일 경로를 지정한다. `.cmd`, `.ps1` 같은 셸 래퍼는 사용하지 않는다.

생성은 [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode)의 `exec --output-schema`를 사용한다. 기존 로그인으로 모델을 호출하며 Codex 이용량이 소모된다. 별도 유료 API 키를 자동 선택하지 않는다. 기본 모델은 설치된 CLI 기본값이며 `--model <이름>` 또는 `SHORTS_CODEX_MODEL`로 지정할 수 있다. 전역 설정은 변경하지 않는다.

각 호출은 최대 300초이고 사용자 설정을 제외한 별도 비대화형 세션에서 JSON을 생성한다. 모델 도구는 비활성화하고 입력 프롬프트에 시리즈·기존 이력과 수정에 필요한 직전 결과를 제공한다. 로그에는 프롬프트, 스키마, 응답, 사용량과 제한된 진단 정보를 저장한다. 인증 파일과 키 값은 읽거나 저장하지 않는다. Codex의 사용자 상태 폴더에 접근할 수 없는 제한 환경에서는 모델 호출 권한 오류를 해결한 뒤 동일 명령으로 재개해야 한다.

## 자동 검사와 수정

- 회차 수, 허용 필드, 안전한 ID, 제목·본문 길이, 유효한 음성 큐를 확인한다.
- 기존 초안·제작·게시 이력과 이번 묶음의 `topicKey`, 제목, 학습 목표를 정규화한 문자열 검사와 모델의 의미 검사로 비교한다. 현재 수정된 회차의 낭독문을 함께 읽고, 핵심 지식이 같은지 판단한다. 중복은 해당 슬롯만 재기획하고, 판단 보류는 TTS 전에 `needs_review`로 멈춘다. [판정 기준과 한계](../novelty/README.md)를 참고한다.
- 시리즈 음성·속도로 실제 합성하고 오디오 해시와 큐 타이밍을 검증한다. 음성은 영상 종료 1초 전까지 끝나야 한다. 종료 후 정지 구간은 30초 영상에서 최대 6초이며, 다른 길이는 `max(2, min(6, duration × 0.25))`초를 적용한다.
- 장면이 전환 시간보다 짧지 않은지, 강조할 카드가 해당 장면에 있는지, 이동 중 새 카드 강조가 너무 빠르지 않은지 검사한다. 회차별 HTML 미리보기와 타임라인도 보존한다.
- 중복 오류에는 비교 이유를 전달해 해당 회차만 다른 핵심 지식으로 재기획한다. 실제 TTS가 실패 회차를 식별한 길이·타이밍 오류는 그 회차의 핵심을 유지하며 수정한다. 실패 회차를 식별할 수 없는 명세 오류는 전체 응답을 다시 요청할 수 있다. 인증·접속·프로세스 오류는 즉시 멈춘다. 음성 미설치 등 환경 오류에서는 후보를 보존하고 환경 해결 뒤 내용 생성 없이 최신 이력 검사와 실측부터 재개한다.
- 모든 회차가 통과하면 잠금 안에서 최신 이력과 한 번 더 비교하고 기획·회차·묶음을 한 번에 등록한다. 도중 실패한 입력 파일은 해당 시도에서 만든 것만 정리한다.

`contentReview.mode: required` 시리즈는 등록 자료의 실제 본문에 대조해 내용 검증을 실행하고, 판정에서 인용한 출처를 기획의 `references`에 저장한다. 자료·후보·보고서 해시를 연결하며 근거 부족은 TTS 전에 멈춘다. `referencesVerified: true`는 등록 자료와의 일치 검증이며 외부 검색이나 최신 웹 원문 조회를 뜻하지 않는다. 미설정·off 시리즈는 기존처럼 `referencesVerified: false`다. [내용 검증 안내](../content/README.md)를 참고한다. 설명의 이해도와 화면의 실제 완성도는 최종 검토 대상이며 자동 승인·게시되지 않는다.

## 기록과 재개

생성 상태·시도별 오류·모델 응답·실측 산출물은 `runs/_generation/<묶음 ID>/`에 남는다. 성공한 기획과 회차 입력은 `planning/catalog.json`, `planning/inputs/`에 저장되어 기존 제작·수정·승인 명령에서 사용할 수 있다.

| 상태 | 의미 |
| --- | --- |
| `generating` | 모델이 기획·대본·장면 JSON을 생성 중 |
| `semantic_check` | 기존 이력과 이번 묶음의 의미 중복 검사 중 |
| `semantic_failed` | 검사 모델 또는 이력 읽기 실패; 저장된 후보로 재개 가능 |
| `content_check` | 실제 근거 자료와 대본·화면 설명 검사 중 |
| `content_failed` | 내용 검사 모델·응답 오류 또는 근거 변경; 저장된 후보로 재개 가능 |
| `needs_review` | 의미 판단·내용 근거 부족, 또는 회차별 재기획·내용 수정·타이밍 보완 횟수 소진; 저장된 이유 검토 필요 |
| `preflighting` | 실제 음성·장면 타이밍 검사 중 |
| `validated` / `committing` | 검사 완료 또는 카탈로그 저장 중 |
| `committed` | 생성 결과가 제작 묶음으로 등록됨; 영상 제작 상태는 `batch status`에서 조회 |
| `failed` | 생성·검사 실패; 오류를 확인하고 같은 명령으로 재시도 |
| `preflight_failed` | 음성 실행 환경 오류; 후보를 보존하고 환경 해결 후 실측부터 재개 |
| `commit_failed` | 검증 후보를 보존했지만 등록 실패; 이력·설정을 확인 후 재시도 |
| `interrupted` | 실행 프로세스가 종료됨; 같은 명령으로 재개 |

같은 묶음 ID와 시리즈·회차 수를 사용하면 등록된 결과를 재사용한다. 다른 시리즈·개수로 바꾸려면 새 ID가 필요하다. 아직 등록하지 않은 후보를 재개할 때는 해시를 확인하고 최신 이력에 대해 의미 검사를 다시 실행한다. 내용 생성 모델 재호출 없이 검사·실측을 재개할 수 있지만 의미 검사 자체에는 모델 호출이 발생한다. 새 중복이 발견되면 해당 슬롯만 대체한다. `--attempts`는 이번 명령의 내용 생성·재기획 호출 수이며, 이력 비교 모델 호출 수는 별도다. 이전에 생성 완료된 묶음은 그대로 재사용하며 의미 검사를 소급 적용하지 않는다.

검토 후 화면 문구·낭독문을 고치려면 `review request-changes`로 요청을 기록하고 `review apply`로 자동 반영·재제작할 수 있다. 음성 입력이 같으면 기존 음성을 재사용한다. 대상 장면·허용 범위·재개 방법은 [자동 수정 안내](../revision/README.md)에 있다. 직접 회차 JSON을 편집한 경우에는 기존 `run <회차 ID>`로 필요한 단계부터 다시 제작한다.
