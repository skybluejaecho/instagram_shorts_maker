# 제작 단계 제목·화면 자동 보완 검증 입력

`original-episode.json`, `original-plan.json`은 이전 CS 기간 자동 제작에서 실제로 보류됐던 maxlen 회차의 그대로인 복사본이다. `archived-hold-report.json`은 당시 내용 검수 보고서에서 개인 PC 경로가 들어 있던 `reportDirectory`, `reportPath` 두 필드만 저장소 상대경로로 정리한 공개용 고정 자료다. 내용 판정·근거·`entryHash`·`sourceHash`는 바꾸지 않았다.

`provenance.json`에는 출처, 현재 파일의 SHA-256, 경로 정리 전 보고서의 `originalFixtureSha256`과 변경 필드를 기록한다. 정리 전 원본은 로컬 감사 기록에 별도로 보존했으며 Git에 포함하지 않는다. 상대경로는 당시 보고서의 위치를 나타내는 기록으로, Git 복제본에 해당 운영 산출물이 있다는 뜻은 아니다.

실제 검증은 다음 명령으로 실행한다.

```powershell
node pipeline/content/validate-repair.cjs
```

매 실행은 별도 검증 시리즈·회차를 만들며 원래 완성 영상 세 편은 변경하지 않는다. 같은 입력·근거 해시로 이전 실제 보류 판정을 한 번 재생하고, 제목·화면 문구의 보완과 내용 재검수에는 실제 Codex 모델을 사용한다. 과거 판정의 재생을 새 모델 판단으로 표시하지 않는다.

음성 재사용은 원본의 실제 WAV·타이밍·단계 키를 검증용 회차에 복사한 뒤 현재 입력과 일치함을 확인해서 시작한다. 자동 보완 뒤 합성 호출 없이 동일한 음성을 쓰며, HTML·화면 검수·MP4·기술 검수는 실제로 수행한다.

별도의 근거 부족 사례는 같은 대본에 Qt 실행 취소 자료만 등록해 실제 내용 검증을 실행한다. 보류 상태·수정 호출 없음·미디어 제작 없음·입력 보존·같은 보류 재실행 시 추가 호출 없음을 확인한다. 결과는 `runs/_content-repairs/validation-<실행 ID>/index.html`에 남긴다.

이 검증은 실제 모델 이용량을 사용한다. 최대 두 번의 보완 제한과 범위 밖 변경, 재개 경계는 별도 자동 테스트도 함께 확인한다. 최종 영상의 승인은 사람이 진행한다.
